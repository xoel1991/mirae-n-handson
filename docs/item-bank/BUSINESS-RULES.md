# 문항 은행(item-bank) — 비즈니스 규칙 후보

> 대상: `legacy/item-bank-php` · 분석 범위: 비즈니스 규칙 후보 (Day 1-2 실습 3)
> 선행 문서: `docs/item-bank/ARCHITECTURE.md`, `docs/item-bank/ERD.md`
> 근거는 저장소 루트 기준 `파일:줄번호` 이다. 아래 경로는 `legacy/item-bank-php/` 접두어를 줄여 `search.php:214` 처럼 적었다. 스키마 파일만 `db/mariadb/init/01-schema.sql` 전체 경로로 적었다.
> **실행 확인**: 검색 규칙 중 "실행 확인" 표시가 있는 것은 2026-09-29 에 기동 중인 레거시(`http://localhost:8081`, 시드 데이터)에 GET 요청을 보내 결과 건수와 경고 문구를 확인했다. 등록(POST)은 DB 에 쓰기 때문에 실행하지 않았다.

## 범위 메모 — "수정 시 검증"

이 모듈에는 **문항 수정 기능이 없다.** 화면은 검색 · 등록 · 단원 목록 3개뿐이다(`index.php:9-11`). 모듈 전체에 UPDATE · DELETE 문도 0건이다(ERD.md §3). 그래서 수정 시 검증 규칙은 적지 않았다.

## 1. 문항 검색 — 노출 대상과 조건 조합

### BR-01 공개 문항만 검색된다
- **규칙**: 문항의 `status` 가 `'A'` 이면 검색 대상이 되고, 그 밖의 상태(`'R'`, `'D'` 등)이면 검색 결과에서 빠진다.
- **근거**: `search.php:522`, `db/mariadb/init/01-schema.sql:68-70`
- **근거 코드**:
  ```php
  $from   = " FROM v_item_public";                 // search.php:522
  ```
  ```sql
  FROM item i
  JOIN unit u ON u.id = i.unit_id
  WHERE i.status = 'A';                            -- 01-schema.sql:68-70
  ```
- **확신도**: 확실
- **비고**:
  - 상태 코드의 뜻(`A=공개 D=삭제 R=검수중`)은 **주석만 있음**(`01-schema.sql:26`). 규칙에는 코드 값만 적었다.
  - 뷰 정의는 `legacy/item-bank-php` 안에 없고 `db/mariadb/init/01-schema.sql:52-70` 에만 있다. 모듈 폴더만 읽으면 필터 조건을 확정할 수 없다(교차 검증 CX-12 가 이 지점에서 "미확인"으로 남겼다).
  - 실행 확인 — 기동 중인 DB 의 뷰 정의(`information_schema.VIEWS`)도 `where i.status = 'A'` 로 스키마 파일과 같다. 상태별 건수는 `A` 26 · `D` 2 · `R` 2 이고, 뷰는 26건이다.

### BR-02 조건이 여러 개면 모두 만족해야 한다 (AND)
- **규칙**: 키워드 · 단원 · 난이도 · 태그 조건이 함께 주어지면 모든 조건을 AND 로 묶어 검색한다.
- **근거**: `search.php:44`, `:98`, `:118`, `:215`, `:218`, `:244`
- **근거 코드**:
  ```php
  $where    = " WHERE 1=1";                          // :44
  $where .= " AND (title LIKE ? OR stem LIKE ?)";    // :98
  $where .= " AND unit_code = ?";                    // :118
  ```
- **확신도**: 확실
- **비고**: 조건끼리 OR 로 묶는 경로는 없다. OR 은 키워드 안에서 제목과 지문 사이에만 있다(BR-03).

### BR-03 키워드는 제목 또는 지문의 부분 일치로 찾는다
- **규칙**: 키워드가 앞뒤 공백을 뺀 뒤 비어 있지 않으면 `title` 또는 `stem` 에 그 키워드가 포함된 문항을 찾는다.
- **근거**: `search.php:85`, `:90`, `:97-98`
- **근거 코드**:
  ```php
  $like = '%' . $q . '%';
  $where .= " AND (title LIKE ? OR stem LIKE ?)";
  ```
- **확신도**: 확실
- **비고**: 실행 확인 — `q=분` 은 14건이었다.

### BR-04 키워드가 100자를 넘으면 100자까지만 쓴다
- **규칙**: 키워드가 100자(멀티바이트 문자 기준)를 넘으면 앞 100자만 검색에 쓰고 경고를 표시한다.
- **근거**: `search.php:86-88`, `:494`
- **근거 코드**:
  ```php
  if (mb_strlen($q, 'UTF-8') > 100) {
      $q = mb_substr($q, 0, 100, 'UTF-8');
      $warnings[] = '키워드가 너무 길어 100자까지만 사용했습니다.';
  ```
- **확신도**: 확실
- **비고**: 매직 넘버 100. 입력칸에도 `maxlength="100"` 이 있다(`:494`). 같은 제한이 서버와 화면 두 곳에 있다.

### BR-05 키워드의 `%` · `_` 는 이스케이프하지 않고 와일드카드로 쓴다
- **규칙**: 키워드에 `%` 나 `_` 가 있으면 경고를 표시하고, 이스케이프하지 않은 채 LIKE 패턴에 넣는다.
- **근거**: `search.php:94-97`
- **근거 코드**:
  ```php
  if (strpos($q, '%') !== false || strpos($q, '_') !== false) {
      $warnings[] = '키워드의 % 와 _ 는 와일드카드로 처리됩니다.';
  }
  ```
- **확신도**: 확실
- **비고**: 실행 확인 — `q=%` 는 조건 없이 검색한 것과 같은 20건이었다.

### BR-06 키워드가 한 글자면 경고만 표시한다
- **규칙**: 키워드가 정확히 한 글자면 경고를 표시하되 검색은 그대로 한다.
- **근거**: `search.php:91-93`
- **근거 코드**:
  ```php
  if (mb_strlen($q, 'UTF-8') === 1) {
      $warnings[] = '키워드가 한 글자라 결과가 많을 수 있습니다.';
  ```
- **확신도**: 확실
- **비고**: 한 글자 검색을 막지는 않는다.

### BR-07 단원은 단원 코드와 일치하는 문항만 찾는다
- **규칙**: 단원 값이 앞뒤 공백을 뺀 뒤 비어 있지 않으면 `unit_code = 입력값` 조건을 건다. **대소문자는 구분하지 않는다**(`m5-1` 도 `M5-1` 과 일치). 형식이 틀리거나, 소문자이거나, 등록되지 않은 코드여도 경고만 표시하고 조회는 그대로 한다.
- **근거**: `search.php:109-120`, `:141-142`, `db/mariadb/init/01-schema.sql:18`
- **근거 코드**:
  ```php
  if (!preg_match('/^[A-Za-z][0-9]{1,2}-[0-9]{1,2}$/', $unit)) {
  ...
  $where .= " AND unit_code = ?";
  ```
  ```sql
  ) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;   -- 01-schema.sql:18 (unit 테이블)
  ```
- **확신도**: 확실
- **비고**:
  - 매직 패턴 `^[A-Za-z][0-9]{1,2}-[0-9]{1,2}$` (예: `M5-1`).
  - **주석과 실제 동작이 다르다.** `:107` 구역 주석은 "단원 코드와 정확히 일치" 라서 대소문자까지 같아야 하는 것처럼 읽힌다(교차 검증 CX-03 이 이 주석대로 "정확히 같을 때만 일치"로 적었다). `:112` 주석은 "형식이 달라도 그대로 조회한다 (결과는 대개 0건)" 이고, `:116` 경고는 "단원 코드는 대문자로 입력하세요. (입력값 그대로 조회합니다)" 이다. 그런데 DB 정렬 규칙이 `utf8mb4_unicode_ci`(대소문자 무시)라서 소문자로 넣어도 일치한다(`db/mariadb/init/01-schema.sql:18`). **실행 확인** — `unit=m5-1` 은 대문자 경고가 뜨면서도 `unit=M5-1` 과 같은 5건이 나왔다. 요약 줄에 단원 이름도 정상으로 표시됐다(`:125` 의 이름 조회도 대소문자를 무시하기 때문).
  - 실행 확인 — `unit=X9-9` 는 "등록되지 않은 단원 코드입니다" 경고와 함께 0건이었다.

### BR-08 난이도를 비워 두면 난이도 5 문항이 빠진다
- **규칙**: 난이도 값이 비어 있으면 `level < 5` 조건을 건다. 따라서 난이도 1~4 문항만 검색된다.
- **근거**: `search.php:213-216`
- **근거 코드**:
  ```php
  // 난이도 값이 비어 있으면 전체 난이도 검색 (1~5 모두 포함)
  if ($level == '') {
      $where .= " AND level < 5";
  ```
- **확신도**: 확실
- **비고**:
  - **주석과 코드가 다르다.** 주석(`:213`)은 "1~5 모두 포함"이지만 코드는 5를 뺀다. 규칙은 코드 기준으로 썼다.
  - 드롭다운의 빈 선택지 라벨도 "전체"다(`:192`). 화면 문구와 실제 동작도 다르다.
  - 시드 주석은 이 동작을 전제로 적혀 있다: "status='A' AND level<5 는 정확히 20건"(`db/mariadb/init/02-seed.sql:34`).
  - 실행 확인 — 조건 없이 검색하면 20건이다. DB 의 공개 문항은 26건이고, 그중 공개(`'A'`) 난이도 5 문항 6건이 빠진다.
  - 매직 넘버 5. 버그인지 의도인지는 코드만으로 알 수 없다. 이관할 때 결정이 필요하다.

### BR-09 난이도가 1~5 한 자리 숫자면 그 난이도만 찾는다
- **규칙**: 난이도 값이 정규식 `^[1-5]$` 에 맞으면 `level = 값` 조건을 건다.
- **근거**: `search.php:217-221`
- **근거 코드**:
  ```php
  else if (preg_match('/^[1-5]$/', $level)) {
      $where .= " AND level = ?";
  ```
- **확신도**: 확실
- **비고**: 실행 확인 — `level=5` 는 6건이었다. 난이도 5 는 이렇게 명시적으로 골라야만 검색된다(BR-08).

### BR-10 난이도가 1~5 형식이 아니면 경고하고, 정수로 바꾼 값으로 그대로 비교한다
- **규칙**: 난이도 값이 비어 있지 않고 `^[1-5]$` 에도 맞지 않으면 경고를 표시하고, PHP `(int)` 로 바꾼 값으로 `level = ?` 비교를 한다.
- **근거**: `search.php:223-229`
- **근거 코드**:
  ```php
  $warnings[] = '난이도는 1~5 사이여야 합니다.';
  $where .= " AND level = ?";
  $values[] = (int)$level;
  ```
- **확신도**: 확실
- **비고**:
  - `:224` 주석은 "1~5 밖의 값은 … (대개 0건)" 이다. 하지만 **형식만 다르고 값은 1~5 인 입력은 결과가 나온다.** 실행 확인 — `level=05` 는 "1~5 사이여야" 경고가 뜨면서도 난이도 5 문항 6건이 나왔다(`(int)'05'` = 5). 경고 문구와 결과가 서로 다르다.
  - 실행 확인 — `level=abc` 는 `(int)'abc'` = 0 이 되어 0건이었다. `level=0` 도 0건이었다.
  - 등록 화면은 같은 1~5 검증에서 **저장을 막는다**(BR-21). 같은 규칙이 두 곳에서 다르게 처리된다.

### BR-11 태그는 태그 이름과 정확히 일치하는 문항만 찾는다
- **규칙**: 태그 값이 앞뒤 공백을 뺀 뒤 비어 있지 않으면, 그 이름의 태그가 달린 문항만 찾는다. 부분 일치는 하지 않는다.
- **근거**: `search.php:235-236`, `:244-247`
- **근거 코드**:
  ```php
  $where .= " AND EXISTS (SELECT 1 FROM item_tag it JOIN tag t ON t.id = it.tag_id"
          . " WHERE it.item_id = v_item_public.id AND t.name = ?)";
  ```
- **확신도**: 확실
- **비고**:
  - 태그는 한 번에 **하나만** 조건으로 쓸 수 있다. 배열로 여러 개를 보내면 첫 값만 쓴다(BR-13).
  - 실행 확인 — `tag=계산` 은 13건이었다. `tag=계` 는 "등록되지 않은 태그입니다" 경고와 함께 0건이었다.
  - `%` 나 `_` 가 있으면 "부분 일치를 지원하지 않습니다" 경고만 낸다(`:237-239`). `=` 비교라서 이 문자들은 글자 그대로 비교된다.

### BR-12 태그가 50자를 넘으면 50자까지만 쓴다
- **규칙**: 태그 값이 50자를 넘으면 앞 50자만 쓰고 경고를 표시한다.
- **근거**: `search.php:240-242`
- **근거 코드**:
  ```php
  if (mb_strlen($tag, 'UTF-8') > 50) {
      $tag = mb_substr($tag, 0, 50, 'UTF-8');
  ```
- **확신도**: 확실
- **비고**: 매직 넘버 50. `tag.name` 컬럼 길이 `VARCHAR(50)` 과 같다(`db/mariadb/init/01-schema.sql:37`).

### BR-13 같은 파라미터가 여러 번 오면 첫 값만 쓴다
- **규칙**: 검색 파라미터(`q`, `unit`, `level`, `tag`, `sort`, `dir`, `page`)가 배열로 들어오면 첫 번째 값만 쓴다.
- **근거**: `search.php:51-80`
- **근거 코드**:
  ```php
  // 파라미터 꺼내기 (배열로 들어오면 첫 값만 쓴다)
  $q = is_array($params['q']) ? (string)reset($params['q']) : (string)$params['q'];
  ```
- **확신도**: 확실
- **비고**: —

## 2. 문항 검색 — 정렬 · 페이지 · 표시

### BR-14 기본 정렬은 난이도 내림차순, 같은 난이도면 ID 오름차순이다
- **규칙**: 정렬 기준이 비어 있거나 알 수 없는 값이면 `ORDER BY level DESC, id ASC` 로 정렬한다. 알 수 없는 값이면 경고도 표시한다.
- **근거**: `search.php:317-326`
- **근거 코드**:
  ```php
  case '':
      // 기본 정렬: 어려운 문항부터, 같은 난이도면 번호 순
      $orderBy = " ORDER BY level DESC, id ASC";
  ```
- **확신도**: 확실
- **비고**:
  - 기본 검색은 난이도 5 가 빠지므로(BR-08), 실제 첫 페이지는 난이도 4 문항부터 나온다. 실행 확인 — 첫 행은 id 18(난이도 4)이다.
  - 실행 확인 — `sort=zzz` 는 "알 수 없는 정렬 기준입니다" 경고와 함께 20건이었다.

### BR-15 정렬 기준별 ORDER BY 와 기본 방향
- **규칙**: `sort` 값에 따라 아래 ORDER BY 를 쓴다. `dir` 이 없으면 `level` · `created` 는 내림차순, `id` · `title` · `unit` 은 오름차순이다. `id` 외 기준은 모두 `id ASC` 를 2차 정렬로 붙인다.

  | sort | dir 없음 · 기본 | 반대 방향 |
  | --- | --- | --- |
  | `id` | `id ASC` | `id DESC` |
  | `title` | `title ASC, id ASC` | `title DESC, id ASC` |
  | `unit` | `unit_code ASC, level DESC, id ASC` | `unit_code DESC, level DESC, id ASC` |
  | `level` | `level DESC, id ASC` | `level ASC, id ASC` |
  | `created` | `created_at DESC, id ASC` | `created_at ASC, id ASC` |

- **근거**: `search.php:276-316` (SQL 의 기본 방향은 각 `case` 의 `else` 분기가 정한다)
- **근거 코드**:
  ```php
  if ($dir === 'asc') {
      $orderBy = " ORDER BY level ASC, id ASC";
  } else {
      $orderBy = " ORDER BY level DESC, id ASC";
  ```
- **확신도**: 확실
- **비고**:
  - 위 인용은 `level` 정렬(`:302-305`)이다. `id` · `title` · `unit` 은 반대로 `if ($dir === 'desc')` 로 분기하고 `else` 가 ASC 다(`:278-297`).
  - `:328-331` 도 `dir` 이 없을 때 방향을 정하지만, 주석대로 **"화면 표시용 기본 방향"**이다. SQL 은 그 전에 이미 조립돼 있어서 조회 결과에는 영향이 없다. 요약 줄의 정렬 표시(`:365`)와 머리글 ▲▼ 표시(`:402-409`)에만 쓰인다.
  - `unit` 정렬은 방향과 관계없이 2차 정렬이 **항상 `level DESC`** 다(`:295`, `:297`).
  - `id` 는 2차 정렬이 필요 없어 붙이지 않는다.
  - `created` 는 열 머리글 링크가 없어 URL 로만 쓸 수 있다(`:392-397`).

### BR-16 정렬 방향은 asc · desc 만 받는다
- **규칙**: `dir` 이 `asc` · `desc`(대소문자 무시)가 아니면 방향을 버리고 BR-15 의 기본 방향을 쓴다. 값이 비어 있지 않았으면 경고도 표시한다.
- **근거**: `search.php:267-273`
- **근거 코드**:
  ```php
  if ($dir !== 'asc' && $dir !== 'desc') {
      if ($dir !== '') {
          $warnings[] = '정렬 방향은 asc 또는 desc 만 가능합니다.';
  ```
- **확신도**: 확실
- **비고**: 실행 확인 — `dir=up` 에서 경고가 나왔다.

### BR-17 열 머리글 정렬 링크는 난이도만 첫 클릭에 내림차순이다
- **규칙**: 현재 정렬 기준이 아닌 열의 머리글 링크는 `dir=asc` 로 만든다. 단 난이도 열은 `dir=desc` 로 만든다. 현재 정렬 기준인 열은 방향을 뒤집는다.
- **근거**: `search.php:400-413`
- **근거 코드**:
  ```php
  } else if ($key === 'level') {
      // 난이도는 첫 클릭에 내림차순
      $nextDir = 'desc';
  ```
- **확신도**: 확실
- **비고**: 화면 동작 규칙. 조회 결과에는 영향이 없다.

### BR-18 한 페이지는 20건이다
- **규칙**: 검색 결과는 한 페이지에 20건씩 보여 주고, `OFFSET = (page - 1) × 20` 이다.
- **근거**: `search.php:349`, `:523`, `:553`
- **근거 코드**:
  ```php
  $offset = ($page - 1) * 20;                           // :349
  $limit  = " LIMIT 20 OFFSET " . (int)$offset;         // :523
  'page_size'    => 20,                                 // :553
  ```
- **확신도**: 확실
- **비고**: 매직 넘버 20 이 **세 곳에 따로** 적혀 있다. 한 곳만 바꾸면 페이지 계산(`renderResultTable` 의 `:684-685`)과 실제 LIMIT 이 어긋난다.

### BR-19 페이지 번호는 1~999 로 보정한다
- **규칙**: `page` 가 숫자만으로 되어 있지 않으면 1페이지로 보고 경고한다(빈 값과 `'1'` 은 경고 없음). 1보다 작으면 1로, 999보다 크면 999로 바꾼다. 999 초과일 때만 경고한다.
- **근거**: `search.php:336-348`
- **근거 코드**:
  ```php
  if ($page < 1) {
      $page = 1;
  }
  if ($page > 999) {
  ```
- **확신도**: 확실
- **비고**:
  - 매직 넘버 999.
  - `page=0` 은 숫자 형식이라 경고 없이 1로 바뀐다. 실행 확인 — 경고 없음, 20건.
  - 실행 확인 — `page=abc` 는 "페이지 번호가 올바르지 않아" 경고, `page=1000` 은 "999 를 넘을 수 없습니다" 경고가 나왔다.
  - 총 페이지 수보다 큰 페이지(예: 5)는 따로 막지 않는다. 표시 건수가 0 인 페이지가 된다. 건수(`id="count"`)는 전체 건수를 보여 준다(코드로 도출, 실행 확인 안 함).

### BR-20 결과가 0건이면 표를 그리지 않고 안내 문구를 보여 준다
- **규칙**: 전체 건수가 0이면 "검색 결과가 없습니다" 를 출력하고 결과 표와 페이지 링크는 출력하지 않는다.
- **근거**: `search.php:657-660`
- **근거 코드**:
  ```php
  if ($total === 0) {
      echo '<p id="message">검색 결과가 없습니다</p>' . "\n";
      return;
  ```
- **확신도**: 확실
- **비고**: 태그 열은 태그 이름을 `tag.id` 순으로 쉼표로 이어 보여 준다(`db/mariadb/init/01-schema.sql:64`). 태그가 없으면 빈칸이다(`search.php:678`).

### BR-21 제목은 앞뒤 공백을 뺀 뒤 5자 이상 200자 이하여야 한다
- **규칙**: 앞뒤 공백을 뺀 제목이 5자 미만이거나 200자 초과이면 오류로 보고 저장하지 않는다.

### BR-23 단원은 등록된 단원 중 하나여야 한다
- **규칙**: 제출한 `unit_id` 가 `unit` 테이블의 `id` 와 문자열로 정확히 일치하지 않으면 오류로 보고 저장하지 않는다.

### BR-24 난이도는 1~5 한 자리 숫자여야 한다
- **규칙**: 앞뒤 공백을 뺀 난이도가 정규식 `^[1-5]$` 에 맞지 않으면 오류로 보고 저장하지 않는다.
- **근거**: `register.php:44`, `:70-72`
- **근거 코드**:

      $errors[] = '난이도는 1~5 사이여야 합니다.';

- **비고**: **같은 규칙이 검색 화면에서는 다르게 구현돼 있다.** 검색은 같은 문구의 경고만 내고 `(int)` 로 바꿔 그대로 조회한다(BR-10). 등록은 저장을 막는다. 스키마에는 1~5 제약이 없다. 범위는 **주석만 있음**(`db/mariadb/init/01-schema.sql:25`).

### BR-25 목록에 없는 태그는 오류 없이 버린다
- **규칙**: 제출한 태그 id 중 `tag` 테이블에 있는 것만 저장하고, 없는 id 는 오류 없이 무시한다.

## 4. 문항 등록 — 저장

### BR-26 새 문항은 검수중(`'R'`) 상태로 저장된다
- **규칙**: 검증을 통과한 문항은 `status = 'R'`, `created_at = updated_at = NOW()` 로 INSERT 한다.
- **근거**: `register.php:92-95`
- **근거 코드**:
  ```php
  "INSERT INTO item (id, unit_id, title, stem, level, status, created_at, updated_at)
   VALUES (?, ?, ?, ?, ?, 'R', NOW(), NOW())"
  ```
- **확신도**: 확실
- **비고**:
  - BR-01 · BR-31 과 합치면, **등록 직후 문항은 검색과 단원 목록 건수 양쪽에 나오지 않는다.** 등록 완료 문구도 그렇게 안내한다(`:116`).
  - 스키마의 기본값은 `'A'` 지만(`01-schema.sql:26`) 코드가 `'R'` 을 명시해서 기본값은 쓰이지 않는다.
  - `R → A` 로 바꾸는 코드는 이 모듈에 없다(ERD.md §4 미확인).

### BR-27 문항 ID 는 현재 최대 ID + 1 로 매긴다
- **규칙**: 새 문항 ID 는 `MAX(item.id) + 1` 로 정하고, 문항이 하나도 없으면 1이다. 트랜잭션 안에서 `FOR UPDATE` 로 조회한다.
- **근거**: `register.php:85`, `:87-90`
- **근거 코드**:
  ```php
  $res = $conn->query("SELECT COALESCE(MAX(id), 0) + 1 AS next_id FROM item FOR UPDATE");
  ```
- **확신도**: 확실
- **비고**: `item.id` 는 AUTO_INCREMENT 가 아니다(`01-schema.sql:21`). 동시 등록에서 안전한지는 미확인(ERD.md §4).

### BR-28 문항과 태그는 한 트랜잭션으로 저장하고, 실패하면 모두 되돌린다
- **규칙**: `item` INSERT 와 `item_tag` INSERT 를 한 트랜잭션으로 묶는다. 어느 하나라도 실패하면 롤백하고 "저장 중 오류가 발생했습니다." 만 표시한다.
- **근거**: `register.php:85`, `:99-100`, `:108-109`, `:114`, `:119-122`
- **근거 코드**:
  ```php
  } catch (Exception $e) {
      $conn->rollback();
      $errors[] = '저장 중 오류가 발생했습니다.';
  ```
- **확신도**: 확실
- **비고**: 원인 메시지는 화면에 내지 않고 로그로만 남긴다(`:121`).

### BR-29 저장에 성공하면 입력칸을 비우고 등록 번호를 알린다
- **규칙**: 저장에 성공하면 "문항 #{id} 을(를) 등록했습니다. 검수 완료 후 검색에 노출됩니다." 를 표시하고 입력값을 모두 비운다.
- **근거**: `register.php:116-118`
- **근거 코드**:
  ```php
  $notice = '문항 #' . $newId . ' 을(를) 등록했습니다. 검수 완료 후 검색에 노출됩니다.';
  $title = $stem = $unitId = $level = '';
  ```
- **확신도**: 확실
- **비고**: 검증에 실패하면 입력값을 유지한 채 폼을 다시 보여 준다(`:144`, `:148`, `:155`, `:164`, `:171`).

## 5. 목록 · 선택지

### BR-30 단원 선택지와 단원 목록은 학년 오름차순, 같은 학년이면 코드 오름차순이다
- **규칙**: 단원을 나열하는 세 곳은 모두 `ORDER BY grade ASC, code ASC` 로 정렬한다.
- **근거**: `search.php:156`, `register.php:27`, `units.php:19`

- **비고**:
  - 검색 폼은 학년별 `optgroup` 으로 묶는다(`search.php:453-455`).
  - 태그 선택지는 `ORDER BY id ASC` 이다(`search.php:178`, `register.php:34`).

### BR-31 단원 목록의 문항 수는 공개(`'A'`) 문항만 센다
- **규칙**: 단원 목록 화면은 단원마다 `status = 'A'` 인 문항 수를 보여 준다. 문항이 없는 단원도 0으로 표시한다.
- **근거**: `units.php:15-19`
- **근거 코드**:
  ```php

    FROM unit u
  ```
- **확신도**: 확실
- **비고**:
  - **같은 "공개" 판정이 두 곳에 따로 구현돼 있다.** 검색은 뷰의 `WHERE i.status = 'A'`(`db/mariadb/init/01-schema.sql:70`)를 쓰고, 단원 목록은 `item` 을 직접 센다. 지금은 조건이 같다.
  - 단원 목록 건수에는 난이도 제한이 없다. 기본 검색의 `level < 5`(BR-08)와 달리 **난이도 5 공개 문항도 센다.** 그래서 단원 목록의 건수 합(26건)과 조건 없는 검색 건수(20건)가 다르다. 실행 확인 — 단원 목록에서 `M5-1` 은 6건인데, 검색 `unit=M5-1` 은 5건이다(시드 기준).
  - `:15` 주석 "삭제 · 검수중 문항은 세지 않는다" 는 코드와 일치한다.
