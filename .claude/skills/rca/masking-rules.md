# RCA 리포트 마스킹 규칙

리포트(`docs/rca/*.md`)를 저장하기 전에 본문 · 표 · 명령 · 명령 출력 전부에 적용한다.

| 유형 | 대상 | 바꾸는 값 |
| --- | --- | --- |
| IP | IPv4 · IPv6 주소(포트 포함) | 역할 별칭. 서버는 `API-1`, `API-2`, `DB-1`, 클라이언트는 `교사단말A`, `교사단말B` … 구분이 필요 없으면 `<IP>` |
| 이메일 | `user@domain` 형식 | `<EMAIL>` |
| 학생 식별자 | `STU-<숫자>` | `<STU>`. 건수만 필요하면 숫자로만 적는다 |
| 토큰 | `Authorization` · `Bearer` · `token=` · `api_key=` · 세션 ID · JWT(`eyJ…`) 값 | `<TOKEN>` |
| 비밀번호 · 접속 문자열 | `password=` · `pwd=` 값, `jdbc:` · `mysql://` URL 안의 계정 · 비밀번호 | `<SECRET>` (호스트도 IP 면 별칭) |

## 역할 별칭

- 같은 주소는 리포트 전체에서 같은 별칭을 쓴다. 역할을 로그에서 근거로 정한다(예: nginx `upstream:` 필드 → 서버, access 로그 클라이언트 주소 → 단말).
- 별칭을 처음 쓰는 곳에 "마스킹한 값이며 다시 실행할 때는 실제 주소를 넣는다"고 적는다.
- 대응표는 작업 중 대화 안에서만 쓰고 파일로 남기지 않는다.

## 적용 후 확인

- 저장 직전 리포트에 다시 검색해 0건인지 확인한다.
  `grep -nE '([0-9]{1,3}\.){3}[0-9]{1,3}|[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}|STU-[0-9]+|eyJ[A-Za-z0-9_-]+|Bearer |password=' docs/rca/<이름>.md`
- 문서 끝에 적용 건수를 적는다: `마스킹 적용: IP N건 · 이메일 N건 · 학생 식별자 N건 · 토큰 N건 · 비밀번호 · 접속 문자열 N건`
