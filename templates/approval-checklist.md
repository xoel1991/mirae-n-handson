# 승인 체크리스트

v1 · 2회차 (2026-10-06)
- "충분한가 · 심각한가 · 지나치게 · 적절하게" 항목을 지우고 모든 항목을 예/아니오 문장으로 바꿨다.
- 치명은 비밀값 노출 · 데이터 손실 두 가지로 한정했고, 테스트 통과는 기존 테스트 기준으로 정했다(새 테스트 누락은 경고).
- 범위 밖 변경은 변경 파일 안의 import 정리만 허용하고, 컨벤션 반려 사유를 계층 · 빈 catch · 표준 출력 · 로그 개인정보로 정했다.

AI 가 만든 변경분 · 외주사 PR 을 머지하기 전에 리뷰어가 대조하는 목록이다. 네 기준의 "판정 항목"이 모두 "예"여야 승인이다. 하나라도 "아니오"면 반려.
"경고 항목"은 판정에 영향을 주지 않는다. "아니오"면 이슈 목록에 경고로 남긴다.

## 심각도 정의

- **치명** — 2번 판정 항목이 "아니오"인 것. 1건이라도 있으면 반려.
- **경고** — 각 기준의 경고 항목이 "아니오"인 것. 승인할 수 있고, 판정표에 기록한다.
- **제안** — 더 나은 방법에 대한 의견. 승인 · 반려에 영향을 주지 않는다. 목록으로만 남긴다.

이슈 한 건은 심각도 · `파일:줄번호` · 근거 · 수정 방향 네 항목으로 적는다. 근거 줄번호를 댈 수 없는 지적은 "확인 필요"로 따로 둔다.

## 1. 테스트 통과

판정 항목

- [ ] 변경된 폴더의 테스트 명령을 이번 리뷰에서 실행했다.
- [ ] 실행 결과의 실패 · 오류가 0건이다.
- [ ] 기존 테스트를 삭제하거나 `skip` · `@Disabled` 로 바꾼 줄이 0줄이다.
- [ ] 이관 코드가 바뀌었으면 `characterization` 의 `npm test` 를 레거시 대상과 새 API 대상으로 각각 실행해 실패가 0건이다.
- [ ] `characterization/` 의 테스트 코드와 `__snapshots__/` 를 고친 줄이 0줄이다(고쳐야 하면 판정을 멈추고 사람에게 묻는다).

경고 항목

- [ ] 새 public 서비스 메서드와 새 엔드포인트마다 테스트가 1건 이상 있다(getter · setter · 생성자 · record 접근자 제외).

## 2. 치명 이슈 0건

판정 항목

- [ ] 비밀번호 · 토큰 · 키 값이 코드 · 설정 · 테스트 픽스처에 리터럴로 들어 있는 곳이 0곳이다(실습용 더미 `app-pass` 제외).
- [ ] 데이터를 삭제하거나 덮어쓰는 새 코드(DELETE · UPDATE 쿼리, `delete*` 호출, 테이블 · 컬럼 DROP)가 있으면 요청 문장에 그 내용이 적혀 있다.

경고 항목

- [ ] SQL 을 문자열로 이어 붙여 만드는 곳이 0곳이다.
- [ ] 외부로 보내는 요청 본문(JSON 등)을 문자열로 이어 붙여 만드는 곳이 0곳이다.
- [ ] 운영 DB 호스트(`prod-db` 등)에 접속하는 명령 · 설정이 0곳이다.
- [ ] `@Transactional` 메서드 안에서 외부 HTTP 호출이나 DB 와 무관한 긴 루프를 도는 곳이 0곳이다.

## 3. 요청 범위 이탈 없음

판정 항목

- [ ] 요청 문장을 한 문장으로 확인했다(없으면 판정하지 않고 먼저 묻는다).
- [ ] 변경 파일 목록의 모든 파일이 요청 문장으로 설명된다.
- [ ] 요청 범위 안의 파일에서 요청과 무관한 변경은 import 정리뿐이다.
- [ ] 의존성 · DB 스키마 · 시드(`db/`) · `application.yml` · `legacy/` 변경이 있으면 요청 문장에 포함돼 있다.

## 4. 컨벤션 준수

판정 항목

- [ ] 컨트롤러 파일에 `Repository` 주입 · `JdbcTemplate` · SQL 문자열이 0건이고, 컨트롤러 반환 타입에 엔티티가 0건이다.
- [ ] 서비스가 다른 도메인의 `Repository` 를 주입하는 곳이 0곳이다.
- [ ] 빈 `catch` 블록이 0개다.
- [ ] `System.out` · `System.err` · `printStackTrace()` · `console.log` 가 0건이다.
- [ ] 로그 메시지에 학생 식별자(`STU-…`) · 이메일 · 토큰 값이 들어가는 곳이 0곳이다.

경고 항목

- [ ] `convention-check` Skill 을 실행했고, 그 결과의 나머지 위반(이름 규칙 · 숫자 리터럴 상수화 · 120자 · 와일드카드 import · `Clock` 미사용)을 이슈 목록에 경고로 옮겼다.

## 판정 형식

첫 줄에 `판정: 승인` 또는 `판정: 반려`. 이어서 네 기준의 충족 · 미충족 표, 그다음 이슈 목록(심각도 · `파일:줄번호` · 근거 · 수정 방향). 코드는 수정하지 않는다.
